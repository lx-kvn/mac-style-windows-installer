套件身分名稱一經發布即不可變更——改了之後系統會把它當成另一個不相關的應用程式並存安裝，而且不會有任何警告。3 到 50 個字元，只能用英文字母、數字、句點、連字號。發行者必須與簽章憑證上記載的名稱完全一致，不一致時系統直接拒絕安裝；上面的「數位簽章」區塊選了憑證時留空即可，工具會自動填入。憑證就在這台機器上時，按下「開始編譯安裝檔」會一路編到底，跟傳統引擎一樣；憑證不在本機（例如交給雲端代簽）時會編到 .msix 為止，之後要自行簽章、再用命令列工具接完後半段。圖示必須是正方形的 PNG，留空即沿用上方那張，三個位置的邊長分別至少要 150、44、50 像素。
決定安裝檔內部用哪一種方式把檔案落地。傳統引擎由 Setup.exe 自己複製檔案、寫登錄表，並附一支解除安裝程式。MSIX 引擎改把應用程式交給 Windows 的套件引擎，由系統保證解除安裝乾淨、不留殘檔，代價是安裝位置與使用者範圍都由系統決定（使用者選不了路徑），且部分設定在這個模式下無法使用——選了之後如果有設定不相容，按下編譯時會一次列出全部不相容的項目。
預設會安裝到 Program Files，需要系統管理員權限（雙擊安裝檔會跳出 UAC 提示）。選「使用者目錄」會改裝到 %LOCALAPPDATA%\Programs\<安裝資料夾名稱>，整個安裝檔（含解除安裝）完全不要求提權。選「自訂路徑」可以自行填寫任意安裝目錄（支援 %APPDATA% 這類環境變數，會依使用者電腦當下的實際值展開），預設視為使用者自己有寫入權限的位置、不要求提權，如果你確定這個路徑需要系統管理員權限才能寫入，請另外勾選下面的選項。
複製檔案之前自動靜默執行這支腳本/執行檔；執行失敗會中止整個安裝並回報錯誤。留空代表不執行。

除了上面內建的 Visual C++ Redistributable / .NET Desktop Runtime，也可以自訂任意相依元件：安裝時用登錄表偵測是否已安裝，缺少的話比照內建元件提示自動下載＋靜默安裝。
目前的「安裝位置」設定不要求系統管理員權限，因此「安裝前建立系統還原點」與「安裝為 Windows 服務」已停用——這兩項都必須有系統管理員權限才能執行，在免權限安裝的流程裡必定失敗。需要這兩項功能的話，請把安裝位置改成 Program Files，或在自訂路徑底下勾選「這個路徑需要系統管理員權限」。
複製檔案之前呼叫 Windows 系統還原功能建立一個還原點，方便使用者在安裝出問題時自行還原系統。部分系統（例如關閉了系統還原功能，或 Windows Server）可能無法建立，失敗只記錄警告，不會阻擋安裝。

打包時把你的應用程式檔案整包加密，終端使用者要先輸入正確密碼才能繼續安裝（這道關卡出現在 EULA 之前）。用途是防止安裝檔被誤傳、亂用，不是拿來擋有心人硬破解的機制，不要用它保護真正機密的內容。「直接輸入密碼」只有這個畫面可以用，密碼不會被寫進任何檔案；需要重複打包或自動化流程，請改用環境變數那個選項，設定檔裡只會記下變數名稱。密碼打錯工具無法幫你檢查，做出來的安裝檔會沒有人打得開，送出前請用「顯示密碼」確認一次。
