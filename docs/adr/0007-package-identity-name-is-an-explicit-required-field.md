# ADR-0007：MSIX 套件身分名稱為獨立必填欄位，不由應用程式名稱推導

## 狀態

已接受（2026-08-31 決定）。決定範圍屬於尚未實作的 MSIX 輸出功能，
規劃見 [`docs/proposals/MSIX輸出規劃.md`](../proposals/MSIX輸出規劃.md)。

## 背景

MSIX 套件清單中的身分名稱（Identity Name）是系統判定「兩包套件是否為同一
應用程式」的唯一依據。該值變更後，系統將新套件視為互不相關的另一個應用
程式：不執行升級，兩者並存安裝，且既有安裝不會被移除。

本專案的打包設定已有 `app_name` 欄位，內容為應用程式的顯示名稱，用於
VERSIONINFO 資源、解除安裝登錄表機碼名稱等處。將身分名稱由 `app_name`
自動推導（清除不合法字元後套用）在技術上可行，且可省去一個必填欄位。

未採用該做法的理由來自一個具體的失效情境：下游專案基於行銷或品牌考量
變更應用程式顯示名稱（例如由 `FileLocker` 改為 `File Locker Pro`）是常見
且合理的決定。若身分名稱由顯示名稱推導，該變更會連帶改變套件身分，而
執行變更的人無從察覺此後果——設定檔上被修改的欄位是「顯示名稱」，其語意
並未提示它同時決定了套件身分。

該情境的後果與
[ADR-0006 背景](0006-msix-mode-has-no-custom-uninstall-ui.md)所述、以及
MSIX 輸出功能規劃中「安裝前偵測並移除傳統模式舊版」所要防止的狀況相同
（新舊版本並存），但嚴重程度更高：傳統模式下並存的兩份安裝可由使用者
手動清除，而套件身分屬於系統層級的識別，變更後既有套件與新套件在系統
眼中不具任何關聯，`upgrade.py` 的既有偵測機制亦無法涵蓋。

## 決定

### 一、身分名稱為獨立必填欄位

打包設定新增一個專用欄位承載 MSIX 套件身分名稱，MSIX 模式下必填，且不
提供由 `app_name` 推導的預設值。

不採用「自動推導但允許覆蓋」這個折衷方案，因為該方案的預設值本身即為
問題所在：會踩到失效情境的使用者，正是不知道需要覆蓋該值的那些人，提供
覆蓋管道對他們沒有作用。

### 二、欄位的不可變性須於範本與文件明示

`builder_cli.py init` 產生的範本設定檔於此欄位放置提示性預留值；
`CLI_USAGE.md` 與使用說明書須明確記載該值一經發布即不可變更，以及變更
後的後果。

### 三、格式檢查於 `validate_and_build_pack_data()` 執行

身分名稱有字元集與長度限制，該檢查比照
[ADR-0003](0003-allow-prerelease-suffix-in-version-string.md) 決定四所
建立的慣例，在 `validate_and_build_pack_data()` 這個純函式中執行，於流程
產生任何副作用（清空 `dist/`、`build/`）之前攔截。

## 後果

- MSIX 模式的設定較傳統模式多一個必填欄位。此成本為一次性，該欄位在
  專案生命週期中填寫一次後不再變動。
- 套件身分與應用程式顯示名稱解耦，下游專案變更顯示名稱不影響升級路徑。

## 已知限制

- 本決定無法防止使用者主動變更身分名稱欄位。決定二的文件記載是唯一的
  防護，工具無從判斷一次變更是誤改或有意為之。
- 傳統模式以 `app_name` 作為解除安裝登錄表機碼名稱、並以此偵測既有安裝
  （`upgrade.check_existing()`），因此傳統模式仍存在「變更顯示名稱導致
  偵測不到舊版」的問題。本決定不處理該問題，僅避免在 MSIX 模式中重現
  一個後果更嚴重的版本。

   以配置精靈的欄位標籤「套件身分名稱」記載，兩份文件的分工不同，並非遺漏。
