# ADR-0002：拖曳安裝改用自繪拖曳，以及隨之而來的四個互動取捨

## 狀態

已接受（2026-08-29 實作完成，`ui/index.html`）。

## 背景

拖曳安裝（把 App 圖示拖到安裝目的地圖示上觸發安裝，詞彙定義見
[`CONTEXT.md`](../../CONTEXT.md)）原本使用瀏覽器內建的 HTML5 拖放：
`#drag-item` 掛 `draggable="true"` 與 `dragstart`，`#drop-target` 掛
`dragover`/`dragleave`/`drop`，靠 `dataTransfer` 傳遞一個
`'install-trigger'` 字串來確認來源。

這條路徑有一個無法繞過的限制：拖曳過程中跟著游標移動的那張影像由作業
系統繪製，網頁端無法控制它的外觀、縮放、透明度，也無法在放開時介入。
因此做不到按下的即時回饋、沒有命中時的彈回、命中時的吸入，而這些正是
這個專案想模仿的 macOS DMG 手感的主要組成。換句話說，整個專案的核心
識別動作，剛好卡在整份介面裡最不能調整外觀的機制上。

## 決定

改為自繪拖曳：用 pointer 事件（`pointerdown`/`pointermove`/`pointerup`/
`pointercancel` 搭配 `setPointerCapture`）自己搬動圖示，位移交給自行
實作的彈簧求解器。以下四個附帶決定，都是在有其他合理選項的情況下做的
取捨，光看程式碼不會知道為什麼。

### 一、彈簧自己寫，不引入動畫函式庫

安裝檔是離線執行的單一 exe，不能在執行期抓取外部資源；把函式庫整包內嵌
雖然可行，但彈簧的核心是同一條「彈簧＋阻尼」方程式，各家差別只在參數的
包裝方式（Apple 講「回彈／多快到位」，多數函式庫講「質量／硬度／阻尼」）。
真正決定手感的是參數與互動規則，不是求解器的實作細節，自己寫約三十行
即可，且沒有版本與授權的牽連。

### 二、用彈簧，而不是固定長度的 CSS 動畫

彈簧的關鍵價值不是「看起來比較彈」，而是它天生從「目前的位置」繼續算，
因此可以在任何一刻被使用者接手：彈回原位的途中再按下去，圖示會從當下
所在位置繼續跟手，不需要等動畫播完，也不會跳位。固定長度的 CSS 動畫
無法平順地被中途抓住並反向，這是選擇彈簧的主要理由。

### 三、命中判定採「重疊即命中」，不採依放開速度推算落點

Apple 的動量投射做法（依放開時的速度推算落點，再吸附到最近的目標）在
可以反悔的動作上很好用——丟進垃圾桶、滑掉一則通知，按錯了都能回頭。
但拖曳安裝的結果是把檔案實際寫進使用者的系統、建立捷徑與登錄表項目，
成本明顯不對稱：少判定一次命中，使用者只是多拖幾公分；多判定一次命中，
使用者會得到一次沒打算執行的安裝。因此只採用「拖曳本體與安裝目的地圖示
的範圍重疊就算命中」，並給 25px 的容差（游標不必壓在目的地上，因為使用者
看的是圖示不是游標尖端），不讓速度參與判定。

### 四、不另外提供「跳過拖曳」按鈕

拖曳本身是這個專案的識別，另外開一條平行的捷徑等同於暗示使用者可以繞過
核心體驗。無障礙的需求由「讓同一個拖曳目標本身支援鍵盤操作」解決（Enter
與空白鍵直接觸發，不播放動畫）；純粹想減少滑鼠動作的效率需求，由既有的
靜默安裝（`/S`）涵蓋，不在 GUI 上另外疊加。

同理，磁吸（靠近目的地時圖示被拉過去）雖然保留，但強度刻意壓到 20%：
它的價值是臨門一腳的暗示，不是提高命中率的主力（那是命中容差的工作），
而每多一分磁吸，就多犧牲一分「東西黏在手上」的跟手感。

## 後果

- 拖曳安裝的行為不再由瀏覽器與作業系統決定，所有時間與曲線都寫在
  `ui/index.html` 開頭一組具名常數裡（`SPRING_BOUNCE`、`SPRING_RESPONSE`、
  `PICKUP_SCALE`、`ABSORB_MS`、`SWALLOW_MS`、`HIT_TOLERANCE`、
  `MAGNET_STRENGTH`），要微調直接改那裡。這些數值是在互動原型上反覆
  拖曳調出來的觀感值，不是推導出來的常數，因此不寫進測試——把它們釘死
  只會擋住往後的微調。
- 測試改為守結構性契約（原生拖曳確實移除、走 pointer 事件並使用
  `setPointerCapture`、原位殘影存在、尊重 `prefers-reduced-motion`、
  鍵盤與滑鼠共用同一個安裝觸發函式），見
  [`tests/test_ui_accessibility.py`](../../tests/test_ui_accessibility.py)。
- 手感本身無法自動化驗證。模擬的滑鼠與鍵盤事件送不進 pywebview 的
  WebView2 內容區（`.claude/skills/run-installer-gui` 的說明也記載了
  同樣的限制），所以每次調整都必須由人在真實視窗上實際拖過才算驗證完成。
