# ADR-0014：憑證存放區模式只以指紋指認憑證，不接受主體名稱比對

## 狀態

已接受（2026-09-05 決定）。尚未實作。不取代任何既有 ADR；
[ADR-0005](0005-installer-never-installs-certificates-into-trust-stores.md)
決定二所述的「寫入本機信任存放區的輔助指令」與本決定無關——那一項處理的是
**信任**存放區，本決定處理的是放置憑證與私鑰的**個人**存放區。

## 背景

`signing` 設定原本只有一種形狀：`cert_path`（`.pfx` 檔案路徑）加
`cert_password_env`（存放密碼的環境變數名稱）。簽章時該密碼以
`signtool /p <密碼>` 的形式出現在命令列上。

2026-09-05 的稽核指出此處的資料安全問題（該次稽核的 S1，見
[`docs/investigations/MSIX稽核與缺陷修正.md`](../investigations/MSIX稽核與缺陷修正.md)）：
同一台機器上的任何行程皆可讀取其他行程的命令列（WMI 的 `Win32_Process`、
Sysmon 的行程建立事件、多數端點防護產品亦會將其寫入日誌），而打包機器正是
存放簽章憑證的所在。本專案在其他位置對此已有防範——密碼不寫入設定檔、簽章
失敗的錯誤訊息不帶入密碼變數——命令列這個出口的暴露面大於前兩者。

`signtool` 未提供以環境變數或標準輸入傳遞 `.pfx` 密碼的選項。使密碼離開
命令列的唯一途徑，是改以「憑證與私鑰置於 Windows 憑證存放區，簽章時以
`/sha1 <指紋>` 指定」的方式簽章：私鑰由作業系統保管，命令列上不出現任何
密碼。

`signtool` 另提供 `/n <主體名稱片段>` 作為指認方式。

## 決定

### 一、新增憑證存放區模式，以 `cert_thumbprint` 啟用

`signing` 新增 `cert_thumbprint` 欄位。填入該欄位即為存放區模式；
`cert_path` 與 `cert_thumbprint` 互斥，同時填入於打包階段報錯。

不另設 `mode` 之類的模式欄位：該旗標的意義將依賴另一個值（填了模式卻未給
指紋時的行為需另行定義），而呼叫端本來就知道自己的憑證在哪裡。此形狀沿用
[ADR-0004](0004-inline-install-password-is-gui-only.md) 對兩種安裝密碼填法
的處置，以及 `builder.build_msix()` 以 `signing` 是否為 `None` 表達分歧的
既有作法。

### 二、只接受指紋，不接受主體名稱

`/n` 的比對為主體名稱的片段比對。存放區中有兩張以上憑證符合該片段時，
`signtool` 不報錯，逕自選用其中一張。

該行為的後果在本工具的兩種引擎下皆不利，而 MSIX 引擎尤甚：套件清單的
發行者欄位必須與實際簽章憑證的主體完全一致，選錯憑證產出的套件會被系統
拒絕安裝，且其錯誤訊息不指向此原因。`msix_settings` 的 `subject.mismatch`
訊息即為防止該情形而寫；接受 `/n` 等同在剛以該訊息封住的位置重新開啟同類
的缺口。

此決定的代價為：指紋為四十個十六進位字元，人不易辨識；且憑證續約換發新的
一張時指紋改變，設定須一併更新。第二項的失敗形態為「找不到指紋為 X 的
憑證」——發生於打包階段、訊息明確指向欄位，屬本專案偏好的失敗形態。

第一項的代價以輸出補償：工具自存放區取得憑證後即可讀出其主體，建置紀錄
輸出「使用憑證：`CN=..., O=...`（指紋 ...）」一行。此輸出亦使
`msix.certificate_subject` 的自動填入在存放區模式下繼續成立。

### 三、兩個存放區皆檢索，不開放設定

檢索範圍為「目前使用者」與「本機電腦」兩者的個人存放區。指紋在定義上唯一，
兩處皆檢索不產生「選錯憑證」的風險；工具依實際找到的位置自行決定
`signtool` 是否帶 `/sm`。

不新增設定欄位讓使用者指定存放區位置：該值為工具查得出的事實，而使用者
答錯的後果是一個「找不到憑證」的欄位。

### 四、檔案模式保留，但於建置紀錄告知其暴露

檔案模式不予移除，亦不標示為棄用：雲端代簽等憑證不在本機的情境未必能改用
存放區模式，且移除為對外契約的破壞性變更。

但保留而不告知等同僅完成一半的修正——S1 的核心正是「使用者不知道該出口
存在」。因此以檔案模式簽章時，建置紀錄輸出一行說明密碼將出現在命令列上，
`CLI_USAGE.md` 亦標明此事。

### 五、新增列出可簽章憑證的子指令

新增子指令列出兩個個人存放區中可用於簽章的憑證及其主體、有效期與指紋，
供使用者取得 `cert_thumbprint` 的值。

該指令只讀取個人存放區，不讀取亦不寫入任何信任存放區，因此與 ADR-0005 的
兩項決定皆不衝突。ADR-0005 決定二所承諾的信任存放區寫入輔助指令至今未
實作，本決定不涵蓋該項。

## 已知限制

- 指紋隨憑證續約而變更，設定檔須一併更新。此為決定二所接受的代價。
- 本決定不改變檔案模式的行為，選用該模式者的密碼仍會出現在命令列上。
- 存放區模式要求憑證與私鑰已置於個人存放區。將 `.pfx` 匯入存放區的動作由
  使用者自行完成（Windows 內建 `Import-PfxCertificate`），本工具不代勞。
