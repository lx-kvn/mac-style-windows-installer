# CI 與本機虛擬機的能力對比

**狀態：對比已完成（2026-09-03）。結論是兩者分工而非擇一，判斷準則見
「分工原則」。文末「待辦清單」列出對比過程中浮現、尚未處理的三項。**

## 動機

`tools/vms.py` 與 `.claude/skills/run-test-vm` 建立之後，專案同時具備兩套
驗證環境。若不先把「各自能做什麼」講清楚，往後每次要驗一件事都得重新判斷
一次該用哪邊，且容易做出錯誤的判斷——例如把「CI 通過了」當成某條路徑已被
驗證，而該路徑其實是 CI 結構上碰不到的。

本文記錄的是實際查證的結果：CI 的部分逐行讀過 `.github/workflows/` 下的
兩份 workflow；虛擬機的部分是實際在兩台機器上執行探測腳本取得的。

## 基準

- CI：`.github/workflows/build.yml`、`.github/workflows/test-packaging-options.yml`
- 虛擬機：`win1809`（Win10 Enterprise LTSC 2019，17763.316，en-US）與
  `win11`（Win11 25H2，26200.8037，zh-TW），皆於 `Clean` 快照上量測
- 量測日期：2026-09-03

## CI 目前實際做了什麼

`build.yml`（每次 push 觸發，`windows-latest`）：跑完整測試套件、編譯打包
工具的 GUI 與 CLI 兩顆 exe、打包成 Setup.exe、上傳建置產物。

`test-packaging-options.yml`（手動觸發，`windows-latest`，兩個 job）：

- `test-packaging-options`：打包一份涵蓋主要欄位的 Setup.exe，靜默安裝到
  用完即丟的 runner 上，驗證登錄表／服務／排程工作／PATH／檔案關聯等系統
  層級效果真的發生，再靜默解除安裝並確認清乾淨。
- `test-msix-engine`：取得 SDK 工具、產生自簽測試憑證並讓該機器信任、一體式
  打包出已簽章的 `.msix` 並內嵌進 Setup.exe、靜默安裝、以 `Get-AppxPackage`
  驗證套件被系統接收、再移除並確認清乾淨。

三個安裝／解除安裝步驟一律為靜默模式（第 105 行 `/S`、第 168 行
`--silent`、第 337 行 `/S`）。

## 對比

| | CI（`windows-latest`） | 本機虛擬機 |
|---|---|---|
| 觸發方式 | 每次 push 自動 | 手動，且需開發者本機開機 |
| Windows 版本 | 僅最新版 | 1809、11 25H2，可再增設 |
| 語言環境 | 僅英文 | 真實 zh-TW（字碼頁 950） |
| 執行身分 | 一律管理員 | 可自行安排 |
| 互動桌面 | 無 | 有 |
| 畫面 | 取不到 | 可截圖 |
| WebView2 Runtime | 必定存在 | `win1809` 必定不存在 |
| 環境乾淨度 | 真正用完即丟 | 快照，需自行維持 |
| 網路 | 有 | `win1809` 無（見下） |
| 結果可及性 | 團隊皆可檢視，紀錄留存 | 僅本機 |

## CI 結構上做不到的三件事

**一、`/S` 以外的安裝路徑從未被執行。** 三個安裝步驟全為靜默模式，因此
拖曳安裝的圖形介面在任何自動化環境中都沒有真正跑起來過。
`.claude/skills/run-installer-gui` 是在開發機上執行的，那不是乾淨環境。

**二、「不使用管理員權限安裝」無法在 CI 上驗證。** runner 本身以管理員身分
執行，該選項在 CI 上恆為通過，但通過不代表正確。此點與 2026-08-11 稽核記錄
的結論一致。

**三、無法製造「缺少某項相依」的情境。** runner 的環境齊備，因此
「缺少 WebView2 Runtime」「沒有 App Installer」這類情境在 CI 上無從重現。

## 虛擬機的量測結果

```
                  win1809                  win11
版本              1809 / 17763.316         25H2 / 26200.8037
語系              en-US                    zh-TW（介面與系統皆是）
WebView2          未安裝                   已安裝 145.0.3800.97
App Installer     無                       有
已裝套件數        33                       105
還原 + 開機       約 6 秒                  約 13 秒
```

兩台皆同：客體帳號 `Tester`、取得的是已提升的權限、寫得進 HKLM 的側載機碼
與 `LocalMachine\Root` 憑證存放區、`Add-AppxPackage` 可用、側載相關登錄值
皆未設值。

`win1809` 不連網路（`ethernet0.startConnected = FALSE`），以確保組建號停在
17763.316——連上網路後 Windows Update 會改變它，環境即不再可重現。檔案傳輸
走 VMware Tools 通道，不需要網路。

## 分工原則

兩者分工，不是擇一。

**CI 是回歸網。** 它的價值在於「每次 push 自動執行、團隊皆可檢視、機器真正
用完即丟」。廣度掃描屬於它：打包是否仍能產出可用的安裝檔、系統層級的效果
是否真的發生、解除安裝是否清得乾淨。這些不搬離 CI。

**虛擬機是專用儀器。** 只承擔 CI 結構上碰不到的項目：舊版本、中文環境、
需要看得見畫面的項目、缺少相依的情境、非管理員身分。

判斷準則：**這件事是否需要「特定的環境」或「看得見」？** 需要則用虛擬機，
不需要則留在 CI。

## 為何歸入 `investigations/`

`adr/` 記錄的是單一決定及其理由，篇幅精簡；本文的主體是查證與量測過程，
篇幅不適合放進 ADR。而 `proposals/` 存放尚未定案的規劃，本文的結論已定案。
形狀上最接近 `investigations/`——實際執行過、有量測數據、有結論——因此歸入
此處，儘管本文並非在追查單一缺陷。

## 已知限制

- 對比僅涵蓋目前存在的兩台虛擬機與兩份 workflow。日後新增 runner 版本或
  虛擬機時，本文的對比表需一併更新。
- 「還原 + 開機」的秒數為單次量測，受主機當下負載影響，僅供量級參考。
- 虛擬機的環境事實取自 `Clean` 快照。若快照被重新拍攝，這些數字即失效。

## 待辦清單

- 於虛擬機內建立一個不具管理員權限的帳號，使「不使用管理員權限安裝」這條
  CI 永遠無法驗證的路徑有處可測。需在 `tools/vms.py` 的機器清單中多記一組
  帳號。
- 評估安裝程式是否應在啟動前偵測 WebView2 Runtime。下方「已完成之待辦」
  記錄的實測結果顯示，缺少該元件時使用者得不到任何線索。此項為功能而非
  驗證，需求尚未釐清，同列於 `docs/proposals/MSIX輸出規劃.md` 待辦第 2 項。

## 已完成之待辦

- **以虛擬機執行拖曳安裝的圖形介面**（2026-09-03）。該路徑先前從未在乾淨
  環境中執行過。以 `run_program(interactive=True)` 在工作階段 1 啟動
  `Setup.exe`，於兩台機器上各執行一次並截圖存證。`win11` 上畫面完整可
  操作，且繁體中文介面顯示正確。
- **驗證缺少 WebView2 Runtime 時安裝精靈的實際行為**（2026-09-03）。結果
  與文件原本的推論不同：視窗會開啟，但版面未正確套用——原本左右並排的
  應用程式圖示與安裝目的地改為由上而下堆疊並溢出視窗，箭頭、核取方塊與
  關閉鈕皆不可見；應用程式名稱停在 `ui/index.html` 的預設佔位文字
  「載入中...」。CSS 與 JavaScript 皆未正常運作，全程不顯示錯誤訊息，
  行程也不結束。同一顆安裝檔在 `win11`（已安裝該元件）上畫面完整，因此
  差異確定來自這個系統元件而非該次建置。

  這比「空白或報錯」更不利：畫面看起來像是仍在載入，使用者不會意識到有
  東西缺失。`docs/使用說明書.md`、`docs/規格文件.md`、`README.md` 中原本
  的敘述已依實測更正。

  未確認的部分如實記載：缺少 WebView2 時實際接手渲染的是哪一個瀏覽器
  引擎（pywebview 在 Windows 上另有 EdgeHTML 與 MSHTML 兩種後備），以及
  安裝路徑那一格是否同樣停在佔位文字——該欄位位於溢出視窗的範圍外，未能
  觀察到。

  過程中另發現一項與本專案無關但屬操作限制的事實：以 `-interactive` 啟動
  位於 `C:\Windows\Temp` 的程式會回報「找不到檔案」——檔案由工作階段 0 的
  提升權限放入，桌面工作階段的使用者讀不到。改置於 `C:\Users\<帳號>` 即可。
  已記入 `.claude/skills/run-test-vm/REFERENCE.md`。
